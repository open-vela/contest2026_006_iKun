## 2. 首页待办数量不实时变化原因

### system.storage 中数据已经变化
在待办页或详情页修改任务完成状态后，`updateTaskStatus()` 已经通过 `storage.set()` 将最新状态持久化到 `system.storage`。

### 为什么 home 仍然读取旧 taskCache
`ensureStorageReady()` 的职责只是确保 Storage 初始化过。一旦 `storageReady === true`，它直接 `Promise.resolve()`，不会重新读取 `system.storage` 中的任务数据。

### ensureStorageReady 与 refreshTasksFromStorage 的区别
- `ensureStorageReady()`：只负责第一次初始化，确保 Storage 模块准备就绪
- `refreshTasksFromStorage()`：从 `system.storage` 重新读取最新任务数据，更新内存中的 `taskCache`

## 3. 首页重新显示刷新

### onShow 原逻辑
```js
onShow() {
  ensureStorageReady().then(() => {
    this.updateTime()
    this.updateStatus()
  })
}
```
只调用 `ensureStorageReady()`，如果已初始化则不会重新读取数据。

### onShow 新逻辑
```js
onShow() {
  ensureStorageReady()
    .then(() => refreshTasksFromStorage())
    .then(() => {
      this.updateTime()
      this.updateStatus()
    })
}
```
先确保 Storage 就绪，然后从 Storage 重新读取最新任务数据，最后刷新页面状态。

### refreshTasksFromStorage 的调用时机
- `onInit()`：首页首次创建时
- `onShow()`：首页每次重新显示时（从待办页/详情页返回）

## 4. 定时器

### 是否保持单一 timer
是，`onInit()` 中创建 timer，`onShow()` 不创建新的 timer。

### 是否避免每秒读取 Storage
是，`setInterval` 只调用 `updateTime()` 和 `updateStatus()`，不调用 `refreshTasksFromStorage()`。
