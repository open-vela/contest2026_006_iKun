# Debug默认数据逻辑优化报告

时间：2026-09-07 11:23

## 一、问题原因

原"重置测试数据"功能会修改 `debug_use_mock_data` 状态，导致：
- 用户关闭开关后，点击重置，开关自动变为开启
- 两个功能职责冲突

## 二、修改文件

| 文件 | 修改内容 |
|------|----------|
| `src/pages/debug/debug.ux` | 修改按钮文字和说明，调用新函数 |
| `src/common/storage.js` | 添加 reloadMockData 函数，删除 resetToMockData |

## 三、开关状态保存逻辑

### 功能定义

| 功能 | 作用 | 影响范围 |
|------|------|----------|
| 默认演示数据开关 | 控制是否显示Mock数据 | 只影响数据显示 |
| 重新加载默认数据 | 更新Mock数据缓存 | 不影响开关状态 |

### 开关状态持久化

```javascript
// 开关状态独立保存
export function setUseMockData(useMock) {
  return new Promise((resolve, reject) => {
    useMockDataCache = useMock
    storage.set({
      key: STORAGE_KEYS.DEBUG_USE_MOCK_DATA,
      value: String(useMock),
      success: function () {
        resolve()
      },
      fail: function (data, code) {
        reject(new Error('Failed to save setting'))
      }
    })
  })
}
```

## 四、重新加载默认数据逻辑

### 新函数实现

```javascript
export function reloadMockData() {
  return new Promise((resolve) => {
    // 重新加载时，不需要做任何操作
    // 因为 getCourses/getExams/getTasks 会动态合并 Mock 数据
    // 只需要确保下次读取时使用最新的 Mock 数据即可
    console.log('Mock data cache will be refreshed on next read')
    resolve()
  })
}
```

### 设计原理

由于 Mock 数据是动态合并的：
```javascript
export function getCourses() {
  if (useMockDataCache) {
    // 每次读取时动态合并
    const userCourseIds = courseCache.map(c => c.id)
    const mockCourses = courses.filter(c => !userCourseIds.includes(c.id))
    return [...mockCourses, ...courseCache]
  }
  return courseCache
}
```

所以"重新加载默认数据"功能实际上不需要做任何操作，因为：
1. Mock 数据来自 `data.js` 文件，每次导入都是最新的
2. 合并逻辑在 `getCourses` 等函数中动态执行
3. 不需要缓存 Mock 数据

### 测试2：重新加载默认数据

**操作**：

2. 点击"重新加载默认数据"

**结果**：
- ✅ 开关仍然关闭
- ✅ 用户数据不受影响

**操作**：打开"默认演示数据"

**结果**：
- ✅ 显示 Mock数据 + 用户数据

### 测试4：关闭默认数据

**操作**：关闭"默认演示数据"

**结果**：
- ✅ 只显示用户数据

### 测试5：重复操作

**操作**：
1. 关闭开关
2. 重新加载默认数据
3. 退出Debug
4. 重新进入Debug

**结果**：
- ✅ 开关状态不会自动变化
