# 默认数据架构变更报告（单源 + Mock ID 过滤）

时间：2026-09-18 00:26

## 1. 问题描述

当前应用采用"Mock + 用户双源合并"的数据架构，Mock 数据受三重保护不可删除不可修改。用户决策：Mock 默认数据应与用户数据同等可删除可修改；debug 页"重新加载默认数据"改为"重置默认数据"以便删除后恢复反复测试。

## 2. 根因分析

- Mock 保护机制散布在数据层（deleteCourse/updateCourse 等拒绝操作）和 UI 层（canDelete=false 隐藏删除按钮、🔒 图标禁止选择）
- reloadMockData() 是空函数无实际作用
- initStorage() 首次启动时不将 Mock 数据写入 storage（getter 运行时合并）

## 3. 修改方案

将数据架构从"双源合并"改为"单源 + Mock ID 过滤"：

1. **所有数据统一存在 storage/cache 中**：首次启动时 Mock 数据深拷贝初始化写入
2. **Mock 数据可删可改**：移除所有 Mock 保护
3. **用"原始 Mock ID 集合"记录哪些是默认数据**：用于开关过滤显示
4. **reloadMockData() → resetToDefaultData()**：恢复 Mock 数据到初始状态，保留用户添加的数据
5. **debug 页按钮文字和说明更新**

## 6. 测试步骤

1. **首次启动**：清除应用数据后启动，首页/课表/考试/待办应显示 Mock 默认数据

2. **删除默认课程**：进入某个 Mock 课程详情页，删除按钮应可见，点击删除应成功，课表中该课程消失

3. **修改默认课程**：进入某个 Mock 课程详情页，点击修改，修改课程名/时间等，保存后应更新成功

4. **重置默认数据**：删除几个默认课程后，进入 debug 页，点击"重置默认数据"，被删除的默认课程应恢复，用户添加的课程应保留

5. **默认演示数据开关**：进入 debug 页，关闭开关，返回首页/课表，Mock 默认数据应消失，用户添加的数据仍显示；重新打开开关，Mock 数据恢复显示

6. **考试历史管理**：进入考试历史页，点击"管理"，所有考试（包括 Mock）都应显示勾选图标（无 🔒），可勾选可删除

7. **删除所有课程**：进入课表设置，删除所有课程，课表应为空；重启应用，课表仍为空（不自动恢复）；点"重置默认数据"后恢复

8. **待办删除/修改**：进入 Mock 待办详情页，删除和修改按钮应可见且可用
