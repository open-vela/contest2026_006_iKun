# 项目修改报告

时间：2026-08-30 18:48

## 一、修改内容

优化 VELA CLASS App 启动性能，减少重复 Storage 读取。

## 二、启动慢的原因

1. **首页 onInit 和 onShow 重复读取 Storage**
   - onInit: `ensureStorageReady()` → `refreshTasksFromStorage()` → `updateStatus()`
   - onShow: `ensureStorageReady()` → `refreshCoursesFromStorage()` + `refreshExamsFromStorage()` + `refreshTasksFromStorage()` → `updateStatus()`
   - 同一份数据被读取两次

2. **updateStatus() 每秒重复计算**
   - 定时器每秒调用 `updateStatus()`
   - 每次都重新计算课程、考试、待办、教学周

## 三、修改文件

- `src/pages/home/home.ux`

## 四、启动流程优化

### 优化前：
```
App启动 → initStorage()
首页 onInit → ensureStorageReady() → refreshTasksFromStorage() → updateStatus()
首页 onShow → ensureStorageReady() → refreshCourses/Exams/Tasks → updateStatus()
定时器 → 每秒 updateStatus()
```

### 优化后：
```
App启动 → initStorage()
首页 onInit → ensureStorageReady() → 直接使用缓存 updateStatus()
首页 onShow → ensureStorageReady() → updateStatus()（不重复读取）
定时器 → 每秒 updateStatus()
```

## 五、性能优化点

1. **移除 onInit 中的 refreshTasksFromStorage()**
   - Storage 初始化完成后，缓存已经是最新数据
   - 不需要再从 Storage 重新读取

2. **简化 onShow 逻辑**
   - 移除 `Promise.all([refreshCourses, refreshExams, refreshTasks])`
   - 直接调用 `updateStatus()` 使用现有缓存
   - 从其他页面返回时仍然能获取最新数据（因为其他页面修改数据时会更新缓存）

3. **移除未使用的 import**
   - 移除 `refreshTasksFromStorage`
   - 移除 `refreshExamsFromStorage`
   - 移除 `refreshCoursesFromStorage`

## 六、测试验证

### 测试步骤：
1. 启动模拟器，观察首页是否正常显示
2. 确认首页显示：时间、日期、课程、考试、待办
3. 进入其他页面后返回首页，确认数据正常刷新
4. 停留在首页，确认时间每秒更新
5. 重启 App，确认数据持久化正常

### 预期效果：
- 首页启动更快（减少重复 Storage 读取）
- 功能完全不变
- 从其他页面返回仍能正常刷新

## 七、性能对比

### 优化前：
- 首页启动时读取 Storage 2-3 次（onInit + onShow）
- 每次进入首页都重复读取所有数据

### 优化后：
- 首页启动时只读取 Storage 1 次（initStorage）
- 首页直接使用内存缓存
- 从其他页面返回时直接更新状态，不重复读取 Storage

## 八、后续建议

1. 如果需要进一步优化，可以考虑将 updateStatus() 中的计算结果缓存
2. 可以考虑将定时器间隔从 1秒 改为更长间隔（如 10秒），因为课程状态不需要每秒更新
3. 首次启动时可以考虑延迟加载非关键数据
