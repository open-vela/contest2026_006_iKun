# 项目修改报告

时间：2026-08-30 20:06

## 一、问题描述

当前 VELA CLASS 项目功能已基本完善，但存在明显的启动延迟问题：

1. OpenVela 模拟器本身已正常启动
2. 从 AIoT 或模拟器应用列表点击启动 VELA CLASS，需要等待约 6～10 秒才真正进入 App
3. 问题与 AIoT 调试入口无关，直接从模拟器启动同样存在延迟
4. **本次任务目标**：精准定位启动延迟的具体原因，而非直接优化

## 二、启动流程分析

根据代码分析，VELA CLASS 的完整启动链路如下：

### 2.1 应用启动阶段（app.ux）

```
APP_CREATE_START
  ↓
INIT_STORAGE_CALL (调用 initStorage())
  ↓
INIT_STORAGE_END (Storage 初始化完成)
  ↓
APP_CREATE_END
```

### 2.2 Storage 初始化阶段（storage.js）

```
INIT_STORAGE_START
  ↓
并行读取 4 个 Storage：
  - COURSES_GET_START → COURSES_GET_DONE
  - EXAMS_GET_START → EXAMS_GET_DONE
  - TASKS_GET_START → TASKS_GET_DONE
  - SEMESTER_GET_START → SEMESTER_GET_DONE
  ↓
INIT_STORAGE_END (等待所有读取完成)
```

**特殊情况**：首次运行时，如果 Storage 中没有数据，会写入默认 Mock 数据。

### 2.3 首页初始化阶段（home.ux）

```
HOME_INIT_START
  ↓
HOME_ENSURE_STORAGE_START (等待 Storage 初始化完成)
  ↓
HOME_STORAGE_READY
  ↓
HOME_STATUS_START (updateStatus 开始)
  ↓
updateStatus 内部调用：
  - getCurrentCourse
  - getNextCourse
  - getNextCourseAcrossDays
  - isTodayCoursesFinished
  - getTodayCourses
  - getNearestExam
  - getExamSummary
  - getTaskSummary
  ↓
HOME_STATUS_END
  ↓
HOME_READY (首页准备就绪)
```

### 2.4 潜在瓶颈点

1. **Storage I/O 操作**：每个 `storage.get` 都是异步操作，可能需要几毫秒到几十毫秒
2. **JSON.parse 操作**：解析存储的 JSON 数据
3. **首次运行写入**：如果没有数据，需要写入默认 Mock 数据
4. **Promise 串行等待**：`ensureStorageReady()` 等待所有 Storage 读取完成
5. **业务计算**：`updateStatus()` 中的多个课程、考试、待办计算

## 四、实际耗时

**注意**：以下为代码分析得出的预期耗时分布，实际测量需要运行 App 并查看控制台日志。

### 4.1 预期耗时分布

| 阶段 | 预期耗时 | 说明 |
|------|----------|------|
| APP_CREATE | < 1ms | 仅调用 initStorage() |
| Storage 初始化 | 10-100ms | 取决于存储 I/O 速度 |
| - courses 读取 | 2-20ms | 包含 JSON.parse |
| - exams 读取 | 2-20ms | 包含 JSON.parse |
| - tasks 读取 | 2-20ms | 包含 JSON.parse |
| - semester 读取 | 2-20ms | 无 JSON.parse |
| HOME_INIT | < 1ms | 仅设置和调用 ensureStorageReady |
| updateStatus | 1-10ms | 业务计算 |
| - getCurrentCourse | < 1ms | 遍历今日课程 |
| - getNextCourse | < 1ms | 遍历今日课程 |
| - getNextCourseAcrossDays | 1-5ms | 遍历未来 7 天 |
| - getTodayCourses | < 1ms | 过滤和排序 |
| - getNearestExam | < 1ms | 过滤和排序 |
| - getExamSummary | < 1ms | 调用 getNearestExam |
| - getTaskSummary | < 1ms | 过滤和计算 |

### 4.2 关键发现

1. **Storage 初始化是串行等待点**：`ensureStorageReady()` 会等待所有 4 个 Storage 读取完成
2. **首次运行会写入默认数据**：如果没有数据，`saveTasksToStorage()` 会额外写入
3. **业务计算很快**：所有计算函数都是纯内存操作，预期耗时 < 10ms

## 五、主要瓶颈

根据代码分析，**主要瓶颈可能在以下位置**：

### 5.1 情况 A：Storage 初始化慢（最可能）

如果 `[PERF:STORAGE] INIT_STORAGE_END (total: Xms)` 显示耗时 > 1 秒，则：
- **主要瓶颈**：Storage I/O 操作
- **具体原因**：OpenVela 的 `@system.storage` 实现可能较慢
- **验证方法**：查看每个 `COURSES_GET_DONE`、`EXAMS_GET_DONE` 等日志的时间戳

### 5.2 情况 B：首页计算慢（不太可能）

如果 `[PERF:HOME] HOME_STATUS_END: Xms` 显示耗时 > 1 秒，则：
- **主要瓶颈**：业务计算
- **具体原因**：需要查看哪个函数最慢
- **验证方法**：查看 `getCurrentCourse: Xms`、`getNextCourseAcrossDays: Xms` 等日志

### 5.3 情况 C：App 代码整体很快（可能）

如果所有 `[PERF:*]` 日志显示总耗时 < 100ms，但用户观察到 6～10 秒延迟，则：
- **主要瓶颈**：不在 App 代码中
- **具体原因**：OpenVela Runtime / 模拟器加载 App 的阶段
- **验证方法**：对比 `APP_CREATE_START` 与用户点击启动的时间差

## 六、问题原因

**待实际测试后确定**。

根据代码分析，最可能的原因是：

1. **Storage I/O 慢**：OpenVela 的 `@system.storage` 实现可能在模拟器上性能较差
2. **Runtime 加载慢**：App 的 Quick App 框架初始化可能较慢
3. **首次运行写入**：首次运行时需要写入默认数据，增加额外 I/O

## 九、下一步优化建议

根据实际测试结果，可能的优化方向：

### 9.1 如果 Storage 初始化是主要瓶颈

1. **并行化读取**：当前已经是并行的，确认是否真并行
2. **减少读取次数**：只在必要时读取
3. **缓存优化**：使用更高效的缓存策略
4. **懒加载**：首页只加载必要数据，其他数据后台加载

### 9.2 如果业务计算是主要瓶颈

1. **缓存计算结果**：避免重复计算
2. **减少遍历次数**：合并多个遍历操作
3. **异步计算**：将计算放到后台

### 9.3 如果 Runtime 加载是主要瓶颈

1. **减少 App 体积**：精简代码和资源
2. **优化 manifest.json**：减少不必要的配置
3. **联系 OpenVela 团队**：反馈性能问题

### 9.4 如果首次运行写入是主要瓶颈

1. **延迟写入**：先显示 UI，后台写入默认数据
2. **减少默认数据量**：精简 Mock 数据
3. **使用更高效的存储方式**：考虑其他存储 API
