# 项目修改报告

时间：2026-09-09 11:52

## 一、实际问题根因

`_scrollToField()` 在键盘刚弹出时立即调用 `getScrollRect()`，此时页面布局尚未完成，`scrollHeight` 返回 0 或过小值，导致 `maxScroll = 0`，最终 `scrollTo` 被限制为 0，页面不滚动。

核心代码逻辑缺陷：
```javascript
// 问题代码
let scrollTo = targetY
if (scrollTo > maxScroll) scrollTo = maxScroll  // maxScroll=0 时，scrollTo 被强制改为 0
el.scrollTo({ top: scrollTo, behavior: 'instant' })
```

## 三、键盘显示后触发滚动时机

```
点击输入框
  ↓
showKeyboard(field)
  ↓
keyboardHidden = false（键盘开始弹出）
  ↓
_scrollToField(field) 开始执行
  ↓
第一阶段延迟 300ms（等待键盘动画完成）
  ↓
getScrollRect 获取滚动范围
  ↓
如果 maxScroll === 0 且重试次数 < 2：
  继续延迟 200ms 重试（第二阶段）
  ↓
获取有效 maxScroll 后执行 scrollTo
```

## 四、getScrollRect 实际返回结构

```javascript
el.getScrollRect((rect) => {
  rect.scrollHeight  // 内容总高度
  rect.height        // 可视区域高度
  rect.scrollX       // 当前水平滚动位置
  rect.scrollY       // 当前垂直滚动位置
})
```

## 五、scrollTo 目标值计算方式

```javascript
const fieldOffsets = { name: 0, teacher: 85, classroom: 170 }  // 课程添加
const fieldOffsets = { classroom: 268 }                         // 考试添加
const fieldOffsets = { title: 0 }                               // 待办添加

const targetY = fieldOffsets[field] || 0

// 只在确认 maxScroll 有效时才限制
let scrollTo = targetY
if (maxScroll > 0 && scrollTo > maxScroll) {
  scrollTo = maxScroll
}
if (scrollTo < 0) scrollTo = 0

el.scrollTo({ top: scrollTo, behavior: 'instant' })
```

## 六、最大滚动距离处理方式

**关键修改**：不再无条件限制 `scrollTo > maxScroll`

```javascript
// 修改前（问题代码）
if (scrollTo > maxScroll) scrollTo = maxScroll  // maxScroll=0 时强制改为 0

// 修改后（安全代码）
if (maxScroll > 0 && scrollTo > maxScroll) {
  scrollTo = maxScroll  // 只在 maxScroll 有效时才限制
}
```

**两阶段延迟策略**：
- 第一阶段：延迟 300ms（等待键盘动画完成）
- 第二阶段：如果 maxScroll 仍为 0，再延迟 200ms 重试
- 最多重试 2 次，不无限循环

## 七、底部安全区域调整

三个页面的 `bottom-safe-space` 均为 200px，足够覆盖键盘遮挡范围（键盘高度约 321px，页面可见区域约 145px）。

## 十、仍存在的限制

1. 字段偏移量使用固定估算值（基于 form-group 高度约 85px），若布局变化需同步调整
2. 300ms + 200ms 延迟基于经验值，极端情况下可能不够
3. 未使用 `visibilityChange` 事件监听键盘状态，依赖手动调用
4. `getScrollRect` 的 `scrollHeight` 在某些情况下可能不包含底部安全区域高度
