# 项目修改报告

时间：2026-09-09 13:31

## 一、实际根因

`_scrollToField()` 函数直接将字段偏移量作为 `scrollTo` 目标值，未考虑键盘遮挡区域。

**原代码问题**：
```javascript
const fieldOffsets = { name: 0, teacher: 85, classroom: 170 }
const targetY = fieldOffsets[field] || 0
el.scrollTo({ top: targetY, behavior: 'instant' })
```

- 顶部字段（name/title）偏移为0，永远滚动到顶部
- 底部字段偏移量未减去键盘高度，输入框仍被遮挡
- 未根据键盘弹出后的实际可视区域计算

## 三、输入框位置计算方式

使用字段底部位置（而非顶部偏移）：

```
course-add: name=85px, teacher=170px, classroom=255px
exam-add:   classroom=341px (4个picker * 64px + 85px)
task-add:   title=85px
```

每个 form-group 高度：label(~21px) + input(52px) + margin(12px) ≈ 85px

## 四、键盘顶部和可视区域计算

```
键盘高度(KEYBOARD_H) = 321px (InputMethod.ux circle模式)
页面高度(PAGE_H) = 466px
scroll容器顶部偏移(SCROLL_TOP) ≈ 80px (padding35px + header45px)

键盘弹出后可见scroll区域 = PAGE_H - KEYBOARD_H - SCROLL_TOP
                        = 466 - 321 - 80 = 65px
```

## 五、scrollTo目标值计算

```javascript
const visibleH = PAGE_H - KEYBOARD_H - SCROLL_TOP  // 65px
const padding = 10  // 底部留白
const needScroll = fieldBottom - visibleH + padding

// 例：classroom字段(fieldBottom=255px)
// needScroll = 255 - 65 + 10 = 200px

let scrollTo = Math.max(0, needScroll)
if (maxScroll > 0 && scrollTo > maxScroll) scrollTo = maxScroll
```

## 六、最大滚动距离处理

通过 `getScrollRect()` 获取实际内容高度，计算 `maxScroll`：
- 如果 `maxScroll === 0` 且重试次数 < 3，延迟200ms重试（等待布局完成）
- 最多重试3次，不无限循环
- 只在 `maxScroll > 0` 时才限制 `scrollTo` 上限

## 七、底部安全区域

三个页面的 `.bottom-safe-space` 保持200px不变，已足够覆盖键盘遮挡范围。

## 十、仍存在的限制

1. `SCROLL_TOP=80px` 为估算值，实际可能因设备/字体设置略有差异
2. 字段高度使用固定值（85px），若表单项高度变化需同步调整
3. 未使用 `visibilityChange` 事件监听键盘状态，依赖 `showKeyboard()` 调用时机
