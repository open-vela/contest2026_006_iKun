# 项目修改报告

时间：2026-08-26 13:31

## 一、修改内容

修改课程添加页面的边缘右滑手势行为，实现两级处理：输入法打开时先关闭输入法，输入法关闭后才返回上一页。删除了额外的"完成"按钮。

## 二、问题原因

- 原"完成"按钮占用标题区域空间
- 手表圆形屏幕空间有限，不适合额外按钮
- 项目已统一使用边缘右滑返回手势

## 三、修改文件

- `src/pages/course-add/course-add.ux`

## 四、实现逻辑

### 1. 删除"完成"按钮
- 移除模板中的 `btn-done` 元素
- 移除 `.btn-done` 和 `.btn-done-text` 样式
- 恢复 `.header` 为简单的列布局

### 2. 修改 onTouchEnd 函数
```javascript
onTouchEnd(e) {
  if (handleTouchEnd(this.gesture, e)) {
    // 如果输入法正在显示，先关闭输入法
    if (!this.keyboardHidden) {
      this.keyboardHidden = true
    } else {
      // 输入法已隐藏，返回上一页
      router.back()
    }
  }
}
```

### 3. 保留 hideKeyboard 函数
`hideKeyboard()` 函数仍被其他代码使用（如 `nextStep`、`openStartPicker`、`openEndPicker`、`saveCourse`），保持不变。

## 五、测试验证

### 测试步骤：
1. 进入添加课程页面
2. 点击输入区域，输入法弹出
3. 左侧边缘右滑 → 输入法关闭，停留在当前页面
4. 已输入内容保持不变
5. 再次左侧边缘右滑 → 返回上一页
6. 在输入法打开时，点击页面其他区域不会关闭输入法
7. 输入法内部正常点击和输入不受影响

### 预期效果：
- 输入法打开时，右滑只关闭输入法
- 输入法关闭后，右滑返回上一页
- 不会误触返回

## 六、后续建议

1. 如果输入法内部滑动与边缘手势冲突，可考虑调整手势阈值
2. 可以考虑在输入法显示时，点击输入区域外的部分关闭输入法
