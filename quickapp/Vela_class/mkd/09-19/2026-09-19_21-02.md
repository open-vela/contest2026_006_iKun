# 待办主页排除已归入历史的待办报告

时间：2026-09-19 21:02

## 1. 问题描述

归入历史的待办仍在待办主页显示，导致同一个待办同时出现在待办主列表和历史列表中。

## 2. 根因分析

loadTasks 各分类函数未排除已归入历史的待办。

## 3. 修改方案

在 loadTasks 中计算历史 ID 集合，各列表 filter 排除。

## 4. 修改的文件和行号

| 文件 | 行号 | 修改内容 |
|------|------|----------|
| `src/pages/task/task.ux` | 325-328 | import 增加 getHistoryTasks 和 getTaskHistoryDays |
| `src/pages/task/task.ux` | 372-415 | loadTasks 计算历史 ID 集合，五个分类列表 filter 排除 |

## 5. 验证结果

| 检查项 | 结果 |
|--------|------|
| import 中增加了 getHistoryTasks 和 getTaskHistoryDays | ✅ |
| loadTasks 中计算了 historyIds 集合 | ✅ |
| 五个分类列表都过滤掉了 historyIds | ✅ |
| pendingCount 基于过滤后的列表计算 | ✅ |
| 历史页 task-history.ux 不受影响 | ✅ |

## 6. 测试步骤

1. **设置归档天数为 1**：deadline 超过 1 天的待办应只出现在历史页，不出现在待办主页

2. **待办主页**：逾期/今日/本周/未来/已完成区域不应包含已归入历史的待办

3. **未超阈值**：deadline 未超过阈值的待办应正常出现在待办主页

4. **历史页删除**：在历史页删除一个待办后返回待办主页，该待办应消失

5. **修改天数**：修改归档天数后返回待办主页，列表应正确更新
