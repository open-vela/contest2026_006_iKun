# 修复待办历史归档逻辑报告

时间：2026-09-19 21:05

## 1. 问题描述

之前移除 finished 筛选导致未完成待办也归入历史，需改回仅已完成归入。

## 2. 根因分析

getHistoryTasks 缺少 finished=true 筛选条件。

## 3. 修改方案

恢复 finished 筛选，归档判断用 deadline，显示移除"未完成"分支。

## 4. 修改的文件和行号

| 文件 | 行号 | 修改内容 |
|------|------|----------|
| `src/common/task.js` | 99-112 | getHistoryTasks 恢复 `if (!t.finished) return false` 筛选条件 |
| `src/pages/task-history/task-history.ux` | 405-413 | loadHistoryTasks 移除"未完成"分支，直接显示完成时间 |

## 5. 验证结果

| 检查项 | 结果 |
|--------|------|
| getHistoryTasks 中有 `if (!t.finished) return false` 筛选条件 | ✅ |
| 归档判断用 parseDateTime(t.deadline) 而非 finishedAt | ✅ |
| 排序按 deadline 倒序 | ✅ |
| task-history.ux 中 finishedText 直接显示完成时间 | ✅ |
| task.ux loadTasks 中排除历史待办 ID 的逻辑未被破坏 | ✅ |

## 6. 测试步骤

1. **未完成待办**：deadline 超过 1 天，应显示在待办主页逾期区域，不出现在历史页

2. **完成待办**：点击完成该待办后，应从待办主页消失，出现在历史页

3. **未超阈值**：已完成待办 deadline 未超过阈值，应显示在待办主页已完成区域，不出现在历史页

4. **Mock 数据**：task_008（finished:true，deadline 9月11日）在 1 天阈值下应出现在历史页

5. **历史页显示**：所有待办都应显示完成时间（如"9月11日完成"），无"未完成"
