## 2. 待办数量不一致原因

### 哪些任务没有进入原来的分组
英语作文（截止 2026-08-18 22:00）在 2026-08-19 已经逾期，但不属于原来的四个分组（今天/本周/以后/已完成），导致它"消失"了。

### 为什么首页数量和页面可见数量不一致
首页 `totalCount` 统计所有 `finished === false` 的任务（包括逾期），但页面只有四个分组，逾期任务无处显示。

## 3. 已逾期分组

### overdue 判断规则
```js
finished === false AND deadline < now
```

### UI 位置
放在待办页面最前面，在"今天"分组之前显示。

### 分类互斥规则
- **已逾期**：截止时间早于当前时间且未完成
- **今天**：今天截止且尚未过期、未完成
- **本周**：本周内、非今天、未过期、未完成
- **以后**：本周之后、未完成

## 4. 任务状态更新

### updateTaskStatus 新实现
使用不可变更新：
```js
taskCache = taskCache.map(task => {
  if (task.id !== taskId) return task
  return { ...task, finished: finished }
})
```

### 是否使用不可变更新
是，创建新数组和新任务对象，不再原地修改。

### rollback 行为
保存旧 `taskCache` 作为 `oldTaskCache`，如果 `storage.set` 失败则回滚。

## 5. Storage 刷新

### refreshTasksFromStorage
从 `system.storage` 重新读取任务数据，生成新的数组和对象，避免引用旧对象。

### 页面什么时候重新读取
- `onInit`：`ensureStorageReady → refreshTasksFromStorage → loadTasks`
- `onShow`：`ensureStorageReady → refreshTasksFromStorage → loadTasks`
- `toggleTask`：`toggleTaskStatus → refreshTasksFromStorage → loadTasks`
- `toggleStatus`（详情页）：`updateTaskStatus → refreshTasksFromStorage → loadTask`

## 6. 完成 / 取消完成流程

### task 页面
```
toggleTask(taskId)
→ toggleTaskStatus(taskId, newStatus)
→ refreshTasksFromStorage()
→ loadTasks()
→ 任务移动到正确分组
```

### task-detail 页面
```
toggleStatus()
→ updateTaskStatus(taskId, newStatus)
→ refreshTasksFromStorage()
→ loadTask()
→ UI 更新（图标、按钮、倒计时）
```

### 状态重新分类方式
重新从 Storage 读取完整任务列表，根据 deadline 和当前时间重新分类到：已逾期/今天/本周/以后/已完成。
