# 项目修改报告

时间：2026-08-26 13:50

## 一、修改内容

将项目所有页面的自定义手势返回机制迁移到 openvela 官方 `onBackPress()` 机制。

## 二、问题原因

- 原项目使用自定义 `gesture.js` + `router.back()` 模拟边缘右滑返回
- 容易与系统默认返回双重触发
- 代码维护成本高

## 三、修改文件

- `src/pages/schedule/schedule.ux`
- `src/pages/exam/exam.ux`
- `src/pages/task/task.ux`
- `src/pages/course-detail/course-detail.ux`
- `src/pages/task-detail/task-detail.ux`
- `src/pages/course-add/course-add.ux`
- 删除 `src/common/gesture.js`

## 四、实现逻辑

### 普通页面迁移

**删除内容：**
- 模板中的 `ontouchstart`、`ontouchmove`、`ontouchend`
- import 中的 `createGestureState`、`handleTouchStart`、`handleTouchMove`、`handleTouchEnd`
- private 中的 `gesture: createGestureState()`
- `onTouchStart`、`onTouchMove`、`onTouchEnd` 函数
- 未使用的 `router` import 和 `goBack()` 函数

**迁移结果：**
- schedule.ux、exam.ux、task.ux、course-detail.ux、task-detail.ux 改用系统默认返回

### course-add.ux 特殊处理

使用 `onBackPress()` 实现两级返回：

```javascript
onBackPress() {
  // 如果输入法正在显示，先关闭输入法
  if (!this.keyboardHidden) {
    this.keyboardHidden = true
    return true // 拦截返回事件，不退出页面
  }
  // 输入法已隐藏，不拦截，让系统执行默认返回
  return false
}
```

### gesture.js 删除

确认所有页面已迁移，删除 `src/common/gesture.js` 文件。

## 六、后续建议

1. 如果发现某些页面需要特殊返回逻辑，可单独添加 `onBackPress()`
2. 不要重新引入自定义手势返回机制
