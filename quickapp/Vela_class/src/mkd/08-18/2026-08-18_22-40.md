## 2. Storage 初始化竞态原因

`initStorage()` 是异步执行的，但 `task.ux` 在 Storage 初始化完成之前就执行了 `loadTasks()`，此时 `taskCache` 仍然是空数组，导致首次进入待办页面时显示为空。

## 3. initPromise 与 ensureStorageReady 实现

### initPromise 单例机制
- 增加 `let initPromise = null` 变量
- `initStorage()` 首次调用时创建 Promise 并保存到 `initPromise`
- 初始化过程中再次调用返回同一个 `initPromise`
- 初始化完成后再次调用直接 `Promise.resolve()`
- 禁止重复初始化 Storage

### ensureStorageReady() 导出
- 如果 `storageReady` 为 true，直接返回 `Promise.resolve()`
- 否则调用 `initStorage()` 等待初始化完成
- 业务页面不需要自己判断 `storageReady`

## 4. task 页面加载时序修改

### onInit
- 导入 `ensureStorageReady`
- 修改为 `ensureStorageReady().then(() => { this.loadTasks() })`
- 确保 Storage 初始化完成后才读取数据

### onShow
- 同样使用 `ensureStorageReady()` 等待初始化完成
- 从详情页返回时也能正确读取最新缓存

## 5. task-detail 页面加载时序修改

### onInit
- 导入 `ensureStorageReady`
- 修改为 `ensureStorageReady().then(() => { this.loadTask() })`
- 确保进入详情页时 Storage 已准备好
